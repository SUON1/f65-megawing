## Honest scope boundary and blockers

The target buffer source is explicitly an **Attic-model**, not real Attic RAM.
`R0C-PLAT-ATTIC-001` is now admitted for a future bounded CPU-copy
`MemoryAccessABI` proof wrapper, but no MAP, DMA, or physical Attic access
service has yet been added or evidenced.
The package is not loaded through a target storage service. No post-ROM-reclaim
storage restoration mechanism is asserted because the required official-platform
evidence/wrapper has not been admitted. `DEC-012` is approved only for a
separate sacrificial R0-C fixture; the target adapter and physical
save-medium/media-fault evidence are still absent.

Consequently, `R0-C GATE PASSED` is not available. The corrective fixture can
be recorded as `R0-C IMPLEMENTATION COMPLETE` only after its corrected build,
host/Xemu validation, guide/evidence update, commit, and origin verification.

## Sacrificial device-9 media fixture update (append-only)

The authorized DEC-012 fixture is implemented as `src/r0c/media_fixture.bas`.
It is a non-production BASIC/DOS proof fixture, not a target storage service or
post-ROM-reclaim wrapper. Every fixture disk operation uses device 9; device 8
is never probed. The transaction writes the inactive generation (`R0CG0` or
`R0CG1`), rereads/verifies it, then writes `R0CSEL`. The `X` action deliberately
pauses after generation verification and before selector I/O, and says when
removal is safe.

Both delivered `R0CMEDIA.D81` and `ROCFINAL.D81` were rejected by the physical
Freezer with `ERROR CODE FF`. The correction is `F65-R0C-MEDIA.D81`. It builds
the known mountable control layout first, retains the proven `R0C-FINAL` and
`R0CPROOF` bytes in their observed locations, then appends `R0C-MEDIA` in a
second C1541 session. `AUTOBOOT` explicitly loads `R0C-FINAL` from device 9;
the fixture is explicitly loaded with `LOAD "R0C-MEDIA",9,1`. There is no
device-8 fallback. Xemu reaches the fixture menu; physical mount, writes, and
faults remain awaiting evidence.

Physical execution exposed that MEGA65 `GET` returns upper-case PETSCII while
the first fixture revision compared an incompatible string representation. The
replacement normalizes PETSCII and ASCII input to ASCII uppercase before every
menu/confirmation dispatch. Host/static normalization checks and Xemu menu boot
pass; the next physical action is initialization on the replacement carrier.

Current fixture identities are recorded in the evidence map and test guide.
